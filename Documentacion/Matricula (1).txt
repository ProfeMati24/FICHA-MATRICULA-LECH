1. CONTEXTO
================================================================

- Software LOCAL, empaquetado como .exe con Electron.
- Repo GitHub de CÓDIGO (este proyecto).
- Repo GitHub de DATOS (distinto, apuntado por github.js).
- github.js IDÉNTICO al de SIDER (token, XOR 'CHARME',
  marcador SIDER-ENC:v1:). No se toca.
- shared.js base de SIDER + helpers de matrícula.
- Paleta y estética heredadas de SIDER (navy #1e3a8a / gold
  #f59e0b, Inter + JetBrains Mono, Lucide, dark mode).
- Seguridad delegada a Electron + .exe + repo privado.
  Contraseña de admin hardcoded en JS (aceptado).

ALCANCE (DECISIÓN FIRME)
------------------------
Este sistema sirve EXCLUSIVAMENTE para matricular alumnos
que ingresan a PRIMERO MEDIO. No gestiona 2°, 3° ni 4° Medio.
Los alumnos ya matriculados en años anteriores dejan de estar
en este sistema: no hay promoción de curso, no hay historial
evolutivo del alumno, no hay egresados.

Cada año escolar constituye una "cohorte" independiente:
  - Cohorte 2027 = todos los que ingresan a 1° Medio en 2027.
  - Cohorte 2028 = todos los que ingresan a 1° Medio en 2028.
  - etc.
Las cohortes no se mezclan en la lógica, aunque comparten el
mismo archivo datos/postulantes.json (ver §4.2).

3. FORMULARIO PÚBLICO (index.html)
================================================================

Formulario dividido en CINCO bloques visuales (cuadros),
cada uno con su propio JS. Envío único al final.

  [Bloque 1] Alumno                        → alumno.js
  [Bloque 2] Apoderado Titular             → apoderado.js
  [Bloque 3] Apoderado Suplente            → apoderado-suplente.js
  [Bloque 4] Términos y Condiciones        → reglas.js
  [Bloque 5] Matrícula, Docs y Firmas      → matricula.js

Orquestación: form.js escucha el submit final, llama a
validar() y getDatos() de cada bloque, arma el objeto
completo, calcula sección + N° matrícula, y persiste.

Sin login: app local, operador único (secretaría).

----------------------------------------------------------------
4.1 AÑO ESCOLAR Y FECHA (API Chile)
----------------------------------------------------------------

Regla: NO se usa la fecha del computador. Se consulta una API
externa para obtener la fecha real de Chile.

Proveedores propuestos (en orden de preferencia):
  1. World Time API
       http://worldtimeapi.org/api/timezone/America/Santiago
  2. TimeAPI.io
       https://timeapi.io/api/Time/current/zone?timeZone=America/Santiago
  3. Fallback: leer header HTTP "Date" de cualquier respuesta
     de GitHub (ya estamos conectados).
  → Si TODAS fallan: mostrar error y NO permitir avanzar
    (no usar reloj del equipo).

Cálculo del año escolar:
  Sea Y = año actual en Chile.
  Opciones mostradas: [Y, Y+1, Y+2, Y+3]
  Ejemplo si hoy es 2027: [2027, 2028, 2029, 2030]
  Ejemplo si hoy es 2028: [2028, 2029, 2030, 2031]

Nota: el año seleccionado identifica la COHORTE (no la
promoción de un alumno). Un alumno matriculado en cohorte
2027 nunca pasa a cohorte 2028 en este sistema.

----------------------------------------------------------------
4.2 N° DE MATRÍCULA
----------------------------------------------------------------

PROPUESTA (necesita confirmar — P19, P20):
  Formato: "AAAA-N"
    · AAAA = año escolar seleccionado
    · N    = correlativo DENTRO de esa cohorte, empieza en 1
  Ejemplo cohorte 2027: 2027-1, 2027-2, 2027-3, ...
  Ejemplo cohorte 2028: 2028-1, 2028-2, 2028-3, ... (reinicia)

  Ventajas:
    · Único a nivel global (dos años no colisionan)
    · Legible para el admin (se ve el año de ingreso)
    · Sin necesidad de "resetear" nada al cambiar de año

  Alternativa simple (si se prefiere): N = (máx global) + 1,
  sin reinicio por año. Más simple pero el N° no dice el año.

  → DECISIÓN REQUERIDA antes de escribir matricula.js.

  Garantía de unicidad: releer postulantes antes de asignar,
  dentro de guardarConReintento.

----------------------------------------------------------------
4.3 ASIGNACIÓN DE SECCIÓN (A → B → C)
----------------------------------------------------------------

- Capacidad por sección configurable en admin (P21).
  Default propuesto: Sección A = máx 30, Sección B = máx 30,
  Sección C = máx 30, Sección D = máx 30.
- Al matricular:
    1. Se recorre la lista de secciones habilitadas
       (A, B, C, ...) en orden.
    2. Se cuenta cuántos matriculados HAY EN LA MISMA
       COHORTE (mismo año) para cada sección.
    3. Se asigna la primera sección con cupo disponible.
    4. Si todas están llenas: error (o lista de espera — P22).
- La capacidad aplica POR COHORTE (cada año tiene sus
  propias A/B/C con sus propios 30 cupos).
- El admin puede sobrescribir la sección manualmente (P23).

- El PDF NO se guarda en el repo. Se descarga/abre en el
  equipo del operador (Electron).
- El PDF es el único lugar donde aparecen las firmas; en
  datos/postulantes.json solo se guardan los datos planos.
- Librería propuesta: jsPDF + html2canvas, o impresión nativa
  de Electron con `webContents.print()`. — P18

  - Buscador y filtros básicos.

  - Editar estado del postulante (catálogo — P24).

NOTA: no hay opción "curso por defecto" en admin, porque el
curso es fijo (Primero Medio). Solo se configura capacidad
por sección y secciones habilitadas.

7. FLUJO DE DATOS
================================================================

1. Secretaría abre la app (.exe).
2. Consulta API Chile → fija año escolar y fecha.
3. Selecciona el año escolar (cohorte) en Bloque 1.
4. Llena Bloques 1–3.
5. Abre PDF de reglas y acepta términos (Bloque 4).
6. Al enviar (Bloque 5):
   - Calcula N° matrícula (AAAA-N, ver §4.2)
   - Calcula sección con cupo dentro de esa cohorte
   - Guarda en datos/postulantes.json (encriptado)
7. Se habilita "Guardar como PDF e imprimir".
8. Admin entra con 2448, filtra por año, gestiona/exporta.
